## Phase 1 — DEMO providers for every stage

Six capabilities previously had no mock: separation, source alignment, target alignment, take analysis, dialogue adaptation and emotion. Mix/export was unreachable without models. Every capability now has a deterministic, labelled `fake` provider (`providers/fake_media.py`, `providers/fake_analysis.py`). The fake transcriber moved behind the registry with bit-identical output.

| Fake | Output | Never claims |
| --- | --- | --- |
| Separator | Dialogue is the unseparated source mix; music/effects are synthetic tones; same 48 kHz float32 stereo shape | Isolation or listening quality |
| Aligner | Evenly spaced placeholder word slots, status `needs_review`, unmeasured performance fields | Forced alignment or acoustics |
| Take analyzer / target aligner | Unmeasured performance, `unalignable` target words, text-derived spans | Pitch, level or Malayalam word timing |
| Dialogue adapter | Current translation plus a rule-based word trim, full prompt provenance | Language-model adaptation |
| Emotion analyzer | New `not_analyzed` status, no scores or labels | Speech-emotion analysis |

Every `fake` job's artifacts are relabelled `demo: true` by the worker, and the UI shows **DEMO** badges. Provider settings are now typed `Literal`s. `allow_demo_providers` (default: allowed outside `CINEDUB_ENV=production`) refuses DEMO jobs and reports DEMO capabilities as unavailable. The browser-test server defaults every model-backed stage to `fake`; existing opt-in variables still select local models.

The take analyzer also has a fake (planned as local-only) because the base-install CI profile has no NumPy. The DEMO path imports no NumPy or ONNX module.

Verification at the Phase 1 commit:

- `tests/api/test_fake_pipeline.py`: one test runs the whole workflow (upload → separate → approve stems → transcribe the dialogue stem → translate → approve → review → adapt → apply → voices → synthesize → takes → align → take analysis → emotion → mix → accepted ZIP with verified checksums). It runs with socket connections forbidden and asserts every fake artifact and provider run is labelled. Two more tests cover the production refusal and each fake's consuming contract.
- Full backend: 365 passed (6 min 32 s). The first attempt used a `--basetemp` inside the repository, and the ASR evaluation correctly refused that path; temp space now lives outside the repo. A second attempt overlapped with uncommitted Phase 2 edits loaded by a subprocess test; that test passed on the restored Phase 1 tree, and the clean full run above is the evidence.
- Browser: 19 passed (including the new `full-pipeline-fake.spec.ts`), 7 opt-in skipped (3.5 min). The new spec is added to the CI base-install selection.
- Ruff, contracts check, strict TypeScript, ESLint and the production build passed.

## Phase 2 — stage registry and typed job contracts

See [ADR 0017](../decisions/0017-stage-registry-typed-jobs.md).

- `cinedub_api.stages` registers 18 stages: 17 requestable plus internal `package_mix`. Each has frozen-input/output contracts, provider routing, ordered preparation steps (per-family modules, original check order) and its processor. The worker dispatch table and `prepare_stage()` derive from it. `jobs.py` no longer branches on stages.
- `JobCreate` is a discriminated union of per-stage requests that rejects options meant for another stage. Requests normalize to the unchanged flat `JobFields`, so v0.2 fingerprints and paid-job reuse are preserved. Every requestable stage is checked against `JobFields` in a parametrized test.
- Create freezes inputs once (it previously ran preparation twice). The worker re-validates stored inputs before any processor runs and validates outputs before recording them. The output check immediately caught a wrong contract guess, `skipped_changed_lines` being a list.
- The generated TypeScript `JobRequest` is now a union of per-stage interfaces; web call sites needed no change.
- Intentional test updates:
  - patch locations moved from `cinedub_api.jobs` / `worker` to `stages.*` / `core_processing`
  - three tests build `JobFields` directly
  - storage-capacity fixtures now insert contract-valid jobs and outputs

  No assertion about product behavior was weakened.
- Deviation from the plan: processors still read the validated `input_json` dict internally. Rewriting every helper to attribute access was judged high-risk/low-value; the ADR records this.

Verification: 392 backend tests passed (27 new contract tests), Ruff, contracts, strict TypeScript, ESLint and the production build passed, and the browser suite passed 19 with 7 opt-in skipped.

## Phase 3 — job runtime: error codes, declared retry, derived status

- `job_errors.py` defines a stable `JobErrorCode` set and a single `classify(exc, job)`. Failures now record codes such as `input_invalid`, `stale_input`, `budget_exceeded`, `provider_timeout`, `deadline_exceeded`, `io_error` and `uncertain_registration` instead of Python class names. Messages still pass through `safe_error`. Typed `StaleInput` and `BudgetExhausted` errors replace plain `ValueError` at the explicit "changed since scheduling" and reservation-exhausted sites. Codes are exported to the TypeScript contracts.
- `RetryPolicy` on each `StageSpec` declares resumability:
  - Transcription keeps its v0.2 remote-resume rules, and its ambiguous submission phase now lives in the policy.
  - Local dialogue adaptation keeps resume after transient failures.
  - Idempotent local stages (ingest, separation, alignment, take/emotion analysis, preview, mix render, export, editorial review) now resume after deadline, I/O, media or process failures. Processors reuse artifacts committed for the same job.
  - Paid stages without a known remote job are never resumable.
  - The resume endpoint asks the policy. The worker has no stage-specific retry or status branches, which a test enforces.
- `project_status.py` derives status (processing > failed > ready > review > draft) from jobs and timeline content. One `sync_project_status()` replaces 13 scattered writes; the column stays for display and backups.
- Intentional behavior change: a cancelled or failed request on a scene with no transcript now reports `draft`, not `review`. Five assertions changed accordingly.
- Job warnings are appended and de-duplicated (`add_warnings`) instead of overwritten.
- The artifact/provider-run helper consolidation was moved to Phase 4, where lineage needs it, so each processor is touched once.

Verification: 423 backend tests passed (31 new runtime tests, including a real transient-failure resume with no duplicate artifacts). Ruff, contracts, strict TypeScript, ESLint and the production build passed. The browser suite passed 19 with 7 opt-in skipped.

## Phase 4 — artifact lineage and storage boundary

See [ADR 0018](../decisions/0018-artifact-lineage-storage.md).

- Migration `0011_artifact_lineage` adds integrity columns (`sha256`, `size_bytes`, root-relative `storage_key`, `provider_run_id`, `lineage_version`) and the `artifact_inputs` edge table. Upgrades from `0010` now take the pre-upgrade database backup.
- `lineage.record_job_lineage()` derives and persists edges once per completed job from frozen inputs and provenance metadata. `backfill_lineage()` reuses the same derivation to idempotently cover pre-v0.3 artifacts at startup. A v0.2 (`0010`) database fixture verifies recorded hashes are kept, unrecorded files are hashed, missing files stay null, and edges are not duplicated on a second backfill.
- `GET /artifacts/{id}/lineage` returns the ancestor graph with producing jobs and provider runs. Accepted bundles include a certificate-hashed `lineage.json`.
- `storage.LocalStorage` owns all job/upload directories, keys, traversal guards, `readable` download checks, usage and project deletion. A structural test rejects media paths built from the storage root elsewhere.
- The DEMO workflow test now asserts that every exported file reaches the uploaded source through recorded edges (roles `source`, `take`, `background:music/effects`, `accepted:*`). It also checks every artifact's recorded hash and size against its bytes and confirms that keys are root-relative.

Verification:

- Full backend run: 424 passed. Two migration tests hard-coded the previous head revision; they now use one `HEAD` constant and pass, together with lineage, backup and recovery (22 passed). The only other change after the full run was a Ruff import-order fix.
- Ruff, contracts, strict TypeScript, ESLint and the production build passed. The browser suite passed 19 with 7 opt-in skipped.

## Phase 5 — correlation IDs, structured logs, startup configuration checks

See [ADR 0019](../decisions/0019-observability-and-config.md). The plan numbered this ADR 0020; the pipeline orchestrator takes 0020 instead.

- Outermost ASGI middleware accepts or mints `X-Request-ID`, echoes it and exposes it through CORS. Migration `0012_correlation_ids` adds `correlation_id` to jobs, provider runs and artifacts. One `before_insert` hook stamps it. The worker binds each job's ID while processing, so one ID traces upload→ingest artifacts and transcribe→provider run→raw transcript (tested).
- API and worker logs are one JSON object per line with service, event, correlation ID and explicit fields. Exceptions log their type only. A test drives a provider exception that contains a fake key through a real job and checks the job error, captured/formatted logs and health/capabilities/project responses.
- `validate_settings()` runs at API and worker startup: fatal for invalid origin/database/storage root, disallowed DEMO providers, or a missing Sarvam key in production; warnings otherwise. `/health` reports warnings, without values.
- Intentional change: the worker's startup line is now the JSON `worker_started` event. The one test that waited for the old free-text line was updated; nothing else (launcher/scripts) consumed it.

Verification: 431 backend tests passed in the full gate. The only failure was that startup-line wait, now passing in isolation. Ruff, contracts, strict TypeScript, ESLint and the production build passed. The browser suite passed 19 with 7 opt-in skipped; this also exercises real API/worker startup with the new logging and validation.

## Phase 6 — pipeline orchestrator with review gates

See [ADR 0020](../decisions/0020-pipeline-orchestrator.md).

- Migration `0013_pipelines`. `POST /projects/{id}/pipelines/plan` previews steps without queueing. `POST /projects/{id}/pipelines` starts a run. Other endpoints: `GET /pipelines/{id}`, `GET /projects/{id}/pipelines`, `POST /pipelines/{id}/continue` (optionally raising the confirmed budget) and `POST /pipelines/{id}/cancel`.
- Jobs go through the shared `jobs.submit_job()` (now also used by `POST /jobs`). Gates open only on explicit continue, and only when saved human state satisfies them. The worker advances after committing each job's outcome; restarts settle active pipelines.
- Tests:
  - The full DEMO pipeline (separation, adaptation and analysis enabled) passes all six gates. Continue is refused before each review exists and before the accepted bundle is packaged. Completion makes the project `ready`.
  - A failed DEMO transcription stops the pipeline and is not resumable.
  - A transient local separation failure resumes the pipeline through the job's resume.
  - Cancel stops the queued job.
  - A simulated worker death mid-step is requeued and continues.
  - A paid (recorded Sarvam) translation pauses with nothing submitted until a sufficient budget is confirmed.

Verification: 438 backend tests, Ruff, contracts, strict TypeScript, ESLint and the production build passed. The browser suite passed 19 with 7 opt-in skipped.

## Phase 7 — API structure, idempotency, events, deletion and cleanup

- `main.py` was split mechanically into `views.py` plus `routes/{diagnostics,projects,uploads,timeline,jobs,events,artifacts}.py`, and is now 97 lines of app wiring. The OpenAPI paths and component schemas were byte-identical before and after the move. A test guards against routes returning to `main.py`.
- Migration `0014_idempotency_keys` adds an optional `Idempotency-Key` on job submission, uploads, pipeline creation and mix review. The same key and body replay the first response; the same key with another body returns 409; entries expire after 24 h. Retried uploads are checked before the active-job guard and are hashed without being stored twice. CORS allows the header.
- `/projects/{id}/events` now streams typed `ProjectEvent`s (`job`, `pipeline`, `project`, `timeline`, `artifact`, `error`, all exported to TypeScript) with incrementing IDs and keepalive comments. It detects changes with count/timestamp tokens instead of serialising every job each second. A reconnect starts from a fresh snapshot rather than a replay. The project detail now includes `latest_pipeline`.
- `DELETE /projects/{id}?confirm=<exact name>` requires the exact project name. It is refused while work or a pipeline is active, or while a non-DEMO cloned voice may still exist at its provider. It removes every owned row (including indirect review/edge rows) and then the project's storage. Other projects are untouched.
- `scripts/storage-cleanup.py` runs as a dry run unless `--apply` is given; `GET /diagnostics/storage` is a read-only report. Cleanup only reports or removes:
  - unreferenced uploads older than the grace period
  - UUID-named leftover project directories
  - expired cancelled or non-resumable failed job directories

  Completed and resumable job directories (including timing provenance such as `raw.wav`), lock files, backups and paths outside the root are never touched.

  A first draft would have flagged unreferenced files inside completed job directories; it was narrowed before commit.

Verification: 443 backend tests passed, including route parity, idempotent replay/conflict, the typed event sequence, deletion guards and cleanup dry-run/apply. Ruff, contracts, strict TypeScript, ESLint and the production build passed. The browser suite passed 19 with 7 opt-in skipped.
