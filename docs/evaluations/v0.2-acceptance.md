# v0.2 acceptance and evidence

This record distinguishes code/integration verification from a provider quality evaluation. It does not mark the complete cinema-dubbing goal finished.

## Implemented workflow

Import English media → FFmpeg preparation → actual audio/video playback and waveform → batch transcription/diarization → editable revision → Malayalam translation → correction/approval → revision-bound SRT export.

The development branch additionally connects approved dialogue → stock-voice assignment → candidate generation → conservative timing fit → explicit take selection → dialogue-only WAV/MP4 preview. Optional offline English ASR is connected through the same revision workflow with manual speakers, not diarization.

Consented-clone preparation/enrollment, explicit voice selection, consent history/revocation and separate provider-deletion jobs are now connected. Local/reference and recorded-provider paths are tested; real Sarvam cloning is not verified.

Reviewed music/effects and selected takes now render stereo PCM24/MP4/SRT with measured loudness, file manifests and separately accepted export bundles. [Mix verification](retained-background-mix.md) records technical and natural-scene listening gates.

## Automated evidence

- API/integration tests cover WAV ingest, byte-range media delivery, revision creation/activation, edit history, timing bounds, incomplete exports, late-response conflicts, active-job deduplication, budgets and restart recovery.
- Migration tests exercise a fresh database and a v0.1 database with approved Malayalam text, including the application's consistent-backup path.
- Sarvam contract tests execute the installed official SDK with a mock HTTP transport and test translation model/style, stock-voice TTS mapping/audio decoding, three-attempt retry bounds, cancellation and ambiguous transport handling. They do not call Sarvam's service.
- Browser tests run real Next.js/API/worker processes with isolated temporary storage. They cover upload, seeking/playback, translation, unsaved drafts, review, SRT downloads, revision switching and reopen. A separate video/narrow-screen case exercises a real FFmpeg proxy.
- Voice/media tests cover explicit take selection, voice-setting invalidation, preserved text approvals, exact stereo sample counts, unsafe-duration rejection, playable audio/video muxing and absence of original source audio in the dialogue-only mix. The browser candidate/render workflow uses demo tones, not speech.
- Optional local-ASR tests cover pinned manifests/checksums, zero API cost, immutable routing, missing diarization, manual speaker creation/assignment, cancellation/deadline termination and worker recovery. The opt-in browser workflow executes the actual installed model on original synthetic speech.
- Cloning tests cover required scope/upload permission, reference timing/format/level validation, explicit enrollment/selection, revoked audio/mix downloads, stock fallback, budget allowances, ambiguous enrollment, revocation during upload and committed-reference recovery. Provider create/clone/delete responses are mocked; the consent browser workflow uses synthetic tones.
- Separation tests cover normalized STFT inversion, overlapping stereo windows, invalid masks/manifests/checksums, no-key process limits/cancellation, source hash changes, checkpoint recovery, output media contracts, approval conflicts/audit history and frozen dialogue-recognition lineage. A separate opt-in browser workflow executes both installed local models with original synthetic audio, explicit stem selection, rerun preservation and rejection. See [measurement and quality limits](local-separation.md).
- Mix tests cover retained stereo frequencies, source-audio exclusion, gains/mutes, sample counts, loudness/peak tolerances, explicit dynamics permission, delayed audio tracks, original-resolution packet preservation, edit/hash conflicts, acceptance/recovery and revoked bundle access. An opt-in browser workflow executes actual separation followed by explicitly labelled demo takes, rendered-video playback and persisted accepted ZIP download.

Run `npm test`, `npm run test:e2e` and `npm run build:web` to reproduce the gates. Passing recorded-response and fixture tests is not proof of live provider accuracy.

Four standard Chrome workflows passed, including real video-proxy seeking, a 390px-wide editor, candidate selection/rendering and reference consent/enrollment/revocation. A fifth opt-in Chrome workflow passed with actual offline recognition and persisted manual speaker assignment. ## Local-model measurement — synthetic scene only

Verification on 2026-10-15: 66 backend tests, contract generation checks, strict TypeScript, Ruff, ESLint and the production build pass. The standard four Chrome workflows and three opt-in workflows cover offline ASR, separation-to-recognition and separation-to-reviewed stereo export with actual browser playback. [The maximum-duration separation run](local-separation.md#two-minute-resource-run-on-2026-10-15) records one 120-second synthetic input; it does not certify natural cinema quality or all laptop workloads.

Pinned model: `Systran/faster-whisper-small.en@d1d751a5f8271d482d14ca55d9e2deeebbae577f`, MIT license; faster-whisper 1.2.1, CTranslate2 4.8.3. CPU int8, four threads, one model process, no batching/GPU. Model storage was 464 MiB. The available GPU was independently detected as RTX 3070 Ti Laptop, 8 GiB VRAM; GPU inference was not tested.

An original 14.8-second two-voice eSpeak scene produced 27 expected words, ignoring punctuation, in 4.484 seconds at 623.5 MiB peak process RSS. Estimated word times are retained in the raw artifact but are not forced alignment. No speaker identities or emotion values were inferred.

Reproduce with the optional setup in the README, generate the fixture, prepare it through normal ingest, then run local transcription. `CINEDUB_E2E_TRANSCRIBER=local npm run test:e2e -- tests/e2e/local-asr.spec.ts` independently exercises the actual model through browser/API/worker. The default browser suite intentionally skips that test. Do not extrapolate one clean synthetic clip to cinema speech, accents, overlapping dialogue or music.

## Required live release gate — pending

No Sarvam key was configured during implementation. Never paste one into chat or commit it. Put it in root `.env` and enable Sarvam routing as described in the README.

1. Generate the original spoken fixture using `python3 scripts/make-evaluation-scene.py`.
2. Import it, transcribe with diarization and translate; confirm requests succeed, remote IDs persist, costs are recorded, and the English/Malayalam text appears in the correct lines.
3. Repeat with a licensed natural scene containing one or two speakers and realistic background audio.
4. Listen and correct the transcript, speaker assignments and phrase boundaries; document recognition/diarization failures rather than hiding them.
5. Have a Malayalam-speaking reviewer record meaning accuracy, naturalness, names, omissions/additions and colloquial suitability on a 1–5 scale. Fix meaning-changing errors before accepting the scene.
6. Edit/approve lines, reopen the project and confirm the exported SRT matches saved timings/text. Retranscribe into a candidate and confirm the reviewed revision is intact.
7. Assign Bulbul v3 stock voices, generate and listen to Malayalam candidates, select takes, and render the dialogue-only preview. Record pronunciation, voice naturalness, pacing and timing fit; do not accept clipped speech or meaning-changing edits to force a fit.

Capture scene identifier/license, duration, provider/model, routing/style, timestamp, request IDs, estimated versus dashboard cost, corrections and reviewer notes in this folder. Keep scene audio, credentials and actor reference recordings in ignored local storage.

## Later-release gates

Live stock-voice listening/timing, real cloning fidelity/consent operational acceptance, natural-scene separation/mix quality, GPU inference/resource measurements and human cinema-quality evaluation remain separate gates. Local natural-scene recognition and speaker-correction effort need benchmarking. Emotion remains unanalyzed in real transcripts.

For cloning acceptance, use an authorized natural reference and verify enrollment/account limits/billing, Malayalam candidate identity/pronunciation, reference performance transfer, revocation and confirmed provider deletion. Record actual costs and any beta failures. Do not upload actor recordings merely to complete an automated test.
